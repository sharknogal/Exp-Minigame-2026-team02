# 공 발사·반사 실행 안내

1. Project 창에서 **BallLaunchPlaytest** 씬을 열고 Play를 누른다. Game 창의 비율은 세로 9:16을 권장한다. 첫 턴은 일반공 1개, 공격력 10으로 시작한다.
2. 마우스를 바닥의 공보다 위에 두면 조준선이 나타난다. 왼쪽 버튼을 누르면 공 위치에서 커서 방향으로 발사한다. 터치는 공 근처에서 시작해 원하는 방향으로 드래그하고 놓는다. 뒤로 당기는 새총 방식이 아니다.
3. 벽·천장에서는 반사한다. 블록에서는 직접 피해와 즉시 특수효과를 먼저 적용한다. 맞은 블록이 살아 있으면 반사하고, 파괴됐으면 그 방향으로 계속 간다.
4. 상점에서 산 공은 취득 순서대로 0.04초 간격으로 출발한다. 첫 공이 바닥에 닿은 가로 위치가 다음 출발점이 된다. 모든 발사가 끝나고 모든 공이 돌아와야 턴이 넘어간다.
5. 화면 상단의 **모든 공 회수** 버튼은 발사 중에만 누를 수 있다. 비행 중인 공과 아직 나가지 않은 공을 함께 회수하며, 자연 복귀가 한 번도 없으면 이전 출발 위치를 유지한다. 바닥에 남는 흰 점은 현재 출발 위치를 표시하는 마커이며 비행 중인 공 수에는 포함하지 않는다. 조준·발사는 카드 선택 중, 일시정지 중, 발사 중, 게임 종료 후에는 받지 않는다.
6. 여러 턴에 걸친 게이지 수치와 공 효과는 기존 시스템을 사용한다. 실제 네 가지 특수 능력의 공격은 이번 기능에 포함하지 않는다.

**추가타 비율 바꾸기:** Project 창에서 `Assets/_Project/Data/BallGaugeBalance.asset`을 선택한다. Inspector에서 **Fire Percent** 등 원하는 항목만 바꾼다. 100은 기존 규칙, 0은 해당 효과의 추가 피해로 게이지를 얻지 않는다는 뜻이다. 직접 피해·블록 체력·충전공 두 배 배율은 바뀌지 않는다. 자세한 계산과 소수 처리 예시는 [밸런스 안내](BallGaugeBalanceTuning.md)에 있다.

테스트 씬에서 화염공을 빠르게 추가하려면 Play 중 조준 상태에서 Hierarchy의 **Ball Launcher → Ball Launch Playtest 컴포넌트 메뉴 → Add Selected Ball (Play Mode)**을 누른다. 기본 Test Ball은 FireBall이다. 이 기능은 실제 구매 없이 한 장을 지급하는 테스트 전용이다.

## 팀 코드와의 연결

- 팀의 SampleScene 파일은 그대로 두고, 저장된 버전을 복사한 전용 플레이 씬에 연결했다. 기존 씬을 복사한 시점 이후 팀 UI가 변경돼도 복사본이 자동으로 갱신되지는 않는다.
- 팀이 원본에 연결할 준비가 되면 저장된 게임 씬을 열고 **Tools → Brick Breaker → Connect Ball Launcher To Active Scene**을 한 번 실행해 배치를 검토한다. 이 메뉴는 현재 씬을 자동 저장하지 않는다. 원본에는 테스트용 카드 지급이나 자동 게임 시작 컴포넌트를 추가하지 않는다.
- 실제 게임의 시작 담당이 `turns.BeginGame()`에 이어 `shots.ResetForNewGame()`을 호출한다. 이후 조준·발사·회수는 `BallShotController`가 담당한다. 다른 입력 코드에서 턴 시작/종료 함수를 중복 호출하지 않는다.
- 상태가 Aiming이고 조준값·소유 공·참조가 유효할 때만 `turns.BeginShot()`을 호출한다. 게이지의 대기 중인 발동을 먼저 처리하고 각 공을 등록해 발사한다. 마지막 복귀/강제 회수 시 `effects.EndShot(id) → gauge.EndShot() → turns.CompleteShot()` 순서로 한 번 처리한다.
- 팀 인벤토리는 공 목록을 내부에 보관하고 종류별 수량만 공개한다. 새 판 시작부터 구매 알림(SelectionChanged)마다 공개 수량 차이를 읽어서 구매 순서를 기록한다. 테스트나 다른 지급 경로가 상점을 거치지 않으면 카드 **한 장을 지급한 직후** `shots.SyncInventory()`를 호출한다. 여러 종류를 이미 지급한 뒤에 늦게 연결한 경우에는 순서를 추측하지 않는다.
- 시작 속도는 10, 유효한 직접 블록 접촉당 +0.3, 상한 24. 벽·천장에서는 가속하지 않는다. 새 공 발사 시 속도를 초기화한다. 10~170도 범위로 조준하며 아래쪽이나 길이가 없는 입력은 무시한다.
- 조준선은 첫 접점과 가상의 반사 한 번까지만 그린다. **미리보기는 피해를 주지 않으므로** 실제 공격으로 블록이 파괴되면 진행 경로가 달라질 수 있다.

## 코드를 읽는 순서

| 파일 | 책임 |
| --- | --- |
| BallAimInput.cs | 마우스와 터치를 조준 방향으로 변환하고 조준선·UI 입력을 구분 |
| BallShotController.cs | 구매한 공의 발사 순서, 턴 상태, 전체 회수와 다음 출발점 |
| BallFlight.cs | 공 하나가 한 물리 시간 동안 이동하고, 적중 결과로 반사·관통·복귀를 결정 |
| BallFlightPath.cs | 반지름 0.10의 원이 지나갈 경로를 검사. 조준선과 실제 공이 같은 계산 사용 |
| BallGaugeBalance.cs / BallDamageService.cs | 종류별 추가타 비율을 실제 감소한 체력에 적용해 피해 기록에 저장 |

Unity 물리 엔진의 CircleCast로 블록의 실제 Collider2D를 찾고, 좌우·천장·바닥은 현재 팀 보드의 고정된 월드 범위(가로 0~6, 세로 0~8)에서 계산한다. 공 프리팹은 표시와 이동을 담당하며 Rigidbody나 별도의 OnCollision 피해 처리를 추가할 필요가 없다. 팀의 보드 크기나 좌표 체계를 바꿀 때에는 이 범위와 격자 조회도 같이 확인해야 한다.
